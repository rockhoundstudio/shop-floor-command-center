# Command Center: Read-Only Report Tools

## Tool Scope
- `list_meta_injector_reports` and `read_meta_injector_report` retrieve captured read-only Command Center reports when callable. They do not load manifests or products, run captures, execute scans or web research, record approvals, perform repairs or saves, upload files, or publish or delete data.
- `gemini_grounded_research` reports represent completed runs published from `/app/sidekick-queue` into the authenticated server-held 30-minute process RAM cache. Direct research execution, local-file or snapshot forwarding to Gemini, and durable process-loss recovery are not performed by these read-only tools.

## Tools
`list_meta_injector_reports` optional parameters: `productId` (format `gid://shopify/Product/<digits>`), `mode` (1-120 chars), `limit` (1-5, default 3), `afterReportId`. Modes: `live_bench_state`, `theme_editor_readback`, `gemini_grounded_research`. Omit `productId` for product-free research; filtering by `productId` excludes null-`productId` records. Follow `pagination.nextAfterReportId` while `pagination.hasNextPage=true`. Use only returned report IDs and cursors.

`read_meta_injector_report` requires `reportId`. Optional parameters: `section`: `report` (default), `ui_audit`; `view`: `chunk` (default), `index`, `header`, `review`, `drawer`, `field`; `chunkIndex`: integer >=0, default 0. Exact `drawer` is required only for `view=drawer`; exact `fieldKey` is required only for `view=field`. Omit unused selectors. Organized views (`index`, `header`, `review`, `drawer`, `field`) apply only to `live_bench_state`; other modes and `ui_audit` use `view=chunk` (or omit `view`).

## Shared Rules
Start chunks at 0; follow `nextChunkIndex` while `hasMoreChunks=true` using identical `reportId`, `section`, `view`, `drawer`, and `fieldKey`. Join chunk text losslessly before JSON parsing. Keep `product`, `theme`, `file`, `reportId`, `session`, and `revision` distinct across snapshots, reports, and views. Superseded or manual captures reflect historical point-in-time state; re-list to check for newer captures.

Cache behavior: process-local RAM, 30-minute base TTL, per-shop and global entry caps, and temporary pins. Process restarts, spin-downs, or separate worker instances do not share RAM entries. Empty cache responses, tool unavailability, or `not_found` statuses indicate only that no matching RAM entry was returned; they do not establish blank product fields, passing checks, or failed or nonexistent research. Report exact returned error codes and partial-coverage indicators accurately.

## Bench: live_bench_state
Match the intended `productId` and `benchSessionId` (the newest capture is not necessarily the active session). Read `index`, `header`, and `review` views first, then `drawer` or `field` views rather than raw chunks when inspecting specific fields. Description Review is read via `view=drawer` with `drawer="Description Review"`. `native_description` and `custom.generated_description` are separate fields across baselines, proposals, approvals, conflicts, and saves. Complete field reviews inspect `header`, `review`, and all applicable drawers, including unchanged fields; an empty `review` drawer alone does not indicate field accuracy.

Field state meanings: `rawStoredBaseline` is the last loaded manifest snapshot rather than a live Shopify read; `evaluatedBaseline` may include template placeholders; `workingState` holds unsaved proposals, edits, or UI approvals. Proposed, approved, and saved states are distinct, and cache sync alone does not write to Shopify or prove storefront DOM rendering.

## Theme: theme_editor_readback
Represents a point-in-time active MAIN-theme snapshot rather than continuous state, Bench state, or unsaved native Theme Customizer edits. Match `capturedAt`, `reportId`, `theme`, `productId`, `runIdentity`, and `selectedEditorFile`. Read `ui_audit` chunks first: `provenanceBoundaries`, `completenessAndCaps`, `savedTemplateOrderIndex`, `thisAppDraftTemplateOrderIndex`, `sharedShellGroupOrderIndex`, `reportSectionPointers`. Then read `report` chunks: template and shared structures, `referencedSectionSchemasAndOptions`, `globalThemeSettings`, `productIdentityAndValues`, `selectedEditorFileReadback`.

Data provenance fields distinguish saved MAIN theme assets (REST Asset API), the app's unsaved selected-file buffer, and native Theme Customizer unsaved state (`UNKNOWN_NOT_CAPTURED_BY_THIS_ROUTE` unless captured). Source and schema order do not establish responsive layout, visibility, or accessibility. Check `sharedShellGroupOrderIndex` / `sharedSectionGroups` (`availability`, `status`, `error`, `parseOk`) and `completenessAndCaps` (`hasNextPage`, `isComplete`, `omittedSectionAssetKeys`); missing or failed asset reads differ from verified empty groups. Static path matching against product values is not live Liquid rendering, and filtered, capped, or unmatched expressions remain unverified.

## Research: gemini_grounded_research
List with `mode="gemini_grounded_research"` and omit `productId` for product-free reports; read one `reportId` at a time from `chunkIndex=0` through completion before parsing `modelSynthesisAnswer`, `sourcesByOriginalChunkIndex`, and `modelAnswerSpanAttributions`. Preserve original `chunkIndex` positions, `uri` values, and `title` strings. Entries in `modelAnswerSpanAttributions` (`groundingSupports`) with `isVerbatimSourceQuotation=false` map model-generated synthesis spans to cited web sources and are not verbatim quotations from source pages. Citation links identify retrieved web sources without independently proving factual accuracy, publication dates, or authorship. `searchEntryPoint` fields contain provider-supplied search suggestion metadata.
